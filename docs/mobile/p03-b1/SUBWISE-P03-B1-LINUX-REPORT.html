上一轮 BLOCKED 的真实根因

  1. Gradle 发行版下载超时：官方 services.gradle.org 返回 307 跳转，wrapper 默认 networkTimeout=10000，下载中直接抛 SocketTimeoutException。构建从未进入编译阶段，上一轮看到的「TLS 握手中断」是表象。
  2. 依赖仓库不可达：repo.maven.apache.org / dl.google.com 同样存在长连接读超时。
  3. 内存与并发不匹配：4 核 3.6GB 上默认 parallel=true + -Xmx2048m，Gradle 守护进程与多个 clang 同时打满内存，swap 耗尽后 IO wait 达 93%，构建卡在换页里零进展（60 秒内 .o 数量不变，进程仍在，表现为「像在跑其实没动」）。

本机环境限制（非产品缺陷）

  • 无 /dev/kvm → 只能 TCG 软件模拟，API 30 启动约 412 秒。
  • API 34 镜像的模拟器被 cgroup OOM kill（qemu 需约 1.7GB anon-rss），故改用 API 30 default 镜像。
  • 模拟器进程本身曾被 OOM kill 2 次 → 跑模拟器前需关闭常驻服务释放内存。
  • adb install（streamed）慢链路会失败，需改用 push + shell pm install。

以上均为本机资源/网络条件所致，不构成对 RN/Expo 路线的否定，也不构成对产品代码的缺陷判定。
